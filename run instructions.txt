
DISASTER RESPONSE COMMAND CENTER — RUN INSTRUCTIONS
=====================================================

REQUIREMENTS
------------
- Python 3.10 or higher
- pip


STEP 1 — Navigate to the project directory
-------------------------------------------
cd disaster-response-dashboard


STEP 2 — Install dependencies
-------------------------------
pip install -r requirements.txt


STEP 3 — Start the backend server
-----------------------------------
uvicorn backend.main:app --reload

The dataset (data/disaster_reports.csv) is generated automatically
on first startup if it does not exist.

Backend URL:  http://127.0.0.1:8000
API docs:     http://127.0.0.1:8000/docs
Health:       http://127.0.0.1:8000/api/health


STEP 4 — Open the frontend
----------------------------
The frontend is served by FastAPI — no separate web server needed.

Landing page:   http://127.0.0.1:8000
Dashboard:      http://127.0.0.1:8000/dashboard


API ENDPOINTS (Phases 1–4)
-----------------------
GET  /api/health                    — Health check
GET  /api/reports                   — List reports (paginated, filterable by 10 criteria)
GET  /api/reports/{report_id}       — Single report details with confidence/priority/conflict breakdowns
GET  /api/reports/priority          — Priority Response Queue (Sorted by Priority DESC)
GET  /api/reports/stale             — Stale reports (>6 hours old)
GET  /api/reports/conflicts         — Reports with detected contradictions
POST /api/reports/{id}/verify       — Update report status (Human-in-the-loop audit logged)
GET  /api/dashboard/stats           — Aggregated dashboard statistics
GET  /api/metrics                   — Algorithm evaluation metrics (Precision, Recall, FPR)
GET  /api/experiments/baseline      — Baseline (FIFO) vs Dashboard Time-to-Surface simulation
GET  /api/experiments/thresholds    — Threshold trade-off evaluation (0.30, 0.50, 0.65)
GET  /api/validation                — Simulated proxy validation study results
GET  /docs                          — Swagger interactive API documentation


STEP 5 — Run Automated Tests
----------------------------
pytest tests/


FRONTEND URLS
-------------
Landing page:   http://127.0.0.1:8000
Dashboard:      http://127.0.0.1:8000/dashboard.html
Reports:        http://127.0.0.1:8000/reports.html
Analytics:      http://127.0.0.1:8000/analytics.html
Methodology:    http://127.0.0.1:8000/methodology.html


NOTES
-----
- Ground truth values, baseline review times, and proxy validation metrics are simulated for evaluation.
- All human verification actions write to append-only log data/verification_audit.json.
- Use --reload for development (auto-restarts on code changes).
